# CYCLE05: Streamlit Web UI & Presentation Layer

## Summary

Cycle 05 focuses on the Presentation Layer. We will build the user interface using Streamlit, providing an interactive dashboard for users to input a GitHub repository and visualize its metrics. This layer strictly separates UI rendering from business logic. It will accept the data models and Polars DataFrames generated by the underlying layers and render KPI cards and charts (Line and Bar) using standard Streamlit components.

## Design Architecture

**Components (`src/presentation/components.py`)**
- A collection of decoupled rendering functions.
- Methods:
  - `render_kpi_metrics(repo_info: RepositoryInfo) -> None`: Uses `st.columns` and `st.metric` to display Stars, Forks, and Issues.
  - `render_commit_trend_chart(df: pl.DataFrame) -> None`: Uses `st.line_chart` to render the date vs. commit count DataFrame.
  - `render_top_committers_chart(df: pl.DataFrame) -> None`: Uses `st.bar_chart` to render the committer vs. commit count DataFrame.
- Constraints: These functions must only accept validated objects (`RepositoryInfo` and `pl.DataFrame`) and execute Streamlit rendering commands. They contain zero data-fetching logic.

**App Dashboard (`src/presentation/app.py`)**
- The main entry point for the Streamlit server (`uv run streamlit run src/presentation/app.py`).
- Manages the layout: Title, Input Form (Text input for "owner/repo", Submit Button), and placeholders for the components.
- Invariants: Must handle the input string validation (ensuring the `owner/repo` format contains a slash) before triggering any underlying controllers.

## Implementation Approach

1. **Init File**: Ensure `src/presentation/__init__.py` exists. Expose components explicitly to maintain package boundaries.
2. **Implement Components**: Create `src/presentation/components.py`. Import Streamlit. Write the rendering functions, passing the data strictly to the Streamlit chart APIs. Ensure Polars DataFrames are converted to Pandas inside the function if required by specific Streamlit versions, though Streamlit natively supports PyArrow/Polars in recent versions.
3. **Implement Main App Skeleton**: Create `src/presentation/app.py`. Set up the page config (`st.set_page_config`). Add the title and the input form using `st.form`.
4. **Input Validation**: Add basic string splitting logic (`repo_input.split('/')`) to extract `owner` and `repo`, raising a `st.warning` if the format is invalid.
5. **Linting and Typing**: Execute `uv run ruff check .` and `uv run mypy .`. Streamlit functions often return `None` which satisfies strict typing.

## Test Strategy

**Unit Testing Approach (Min 300 words)**
Testing Streamlit UI components directly via Pytest is challenging due to the underlying server thread constraints. Our strategy relies on strict decoupling: we test the wrapper functions by mocking the Streamlit module itself. Using `unittest.mock.patch`, we will mock `st.metric`, `st.line_chart`, and `st.bar_chart`. We will then instantiate a dummy `RepositoryInfo` object and dummy Polars DataFrames. By passing these mock objects into our `components.py` functions, we will assert that the underlying Streamlit API was called exactly once with the correct arguments (e.g., asserting that `st.metric` was called with the label "Stars" and the integer value from our mock `RepositoryInfo`). This ensures the presentation logic routes the data correctly without spinning up a live browser session.

**Integration Testing Approach (Min 300 words)**
Integration testing for the UI involves verifying the input validation logic within `app.py`. We will extract the string validation function (which checks for the `owner/repo` pattern) into a separate, pure Python function. We will then feed various inputs into this function, including valid formats (`streamlit/streamlit`), invalid formats without slashes (`invalidrepo`), formats with too many slashes (`owner/repo/extra`), and empty strings. The test will assert that the function correctly parses valid inputs into a tuple `(owner, repo)` and correctly raises a defined ValueError or returns a specific error state for all invalid formats, proving the UI will effectively guard the downstream API client from malformed requests.
